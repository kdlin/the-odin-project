HTML + CSS Practical Refresher

The load-bearing HTML & CSS you actually reach for daily — curated, no trivia. Use as a pre-project warm-up and a quick lookup.

Total: ~15 min · HTML structure, selectors, cascade, box model, display, units, Flexbox, positioning

Scope Everything here is stuff you'll type in real projects. Edge cases and obscure properties are deliberately left out — look those up when a project needs them. For Grid, see the dedicated Grid Review lesson (use the Lessons button below).

1. HTML skeleton ⏱ 1 min

<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="UTF-8">
    <meta name="viewport" content="width=device-width, initial-scale=1.0">
    <title>Page Title</title>
    <link rel="stylesheet" href="style.css">
  </head>
  <body>
    <!-- content -->
  </body>
</html>

<head> = metadata (not visible). <body> = visible content. The viewport meta is what makes mobile scaling work — always include it.

2. Semantic elements (use these, not div-soup) ⏱ 1 min

The structural tags you should default to
header nav main section article aside footer — describe meaning, not just boxes.
h1–h6 headings (one h1 per page), p, ul/ol/li, a, img, button.
Why it matters Semantic tags give you accessibility (screen readers), SEO, and readable code for free. Reach for div/span only when no semantic tag fits (generic block / inline wrappers).

3. Links, images, lists ⏱ 1 min

<a href="https://example.com">text</a>          <!-- absolute -->
<a href="about.html">About</a>                  <!-- relative -->
<img src="cat.jpg" alt="a cat">                 <!-- alt is required -->
<ul><li>item</li></ul>                          <!-- unordered -->
Trap: alt text Always write alt on images — it's read by screen readers and shows if the image fails. Empty alt="" is correct only for purely decorative images.

4. Selectors ⏱ 2 min

.class      { }   /* class      - reusable, your default */
#id         { }   /* id         - unique, avoid for styling */
element     { }   /* tag        - all of that element */
.a .b       { }   /* descendant - .b anywhere inside .a */
.a > .b     { }   /* child      - .b directly inside .a */
.a, .b      { }   /* group      - both */
a:hover     { }   /* pseudo-class - state */
li::before  { }   /* pseudo-element - generated content */
Practical default Style with classes. Reserve id for JS hooks / anchors, not styling (too specific, not reusable).

5. The cascade: specificity & inheritance ⏱ 2 min

When rules conflict, the winner is decided by specificity, then source order (last wins on a tie).

Specificity, high to low
inline style > #id > .class / :pseudo-class / [attr] > element / ::pseudo-element
!important overrides all of the above (avoid it — it's a smell).
Trap: fighting specificity If a style "won't apply," something more specific is winning. Don't pile on !important — lower the other selector's specificity or raise yours with a class. Inheritance: some properties (color, font) pass to children automatically; layout ones (margin, padding, border) do not.

6. The box model ⏱ 2 min

Every element is boxes nested outward: content → padding → border → margin.

margin (outside, space between elements)
content + padding (inside) + border
* { box-sizing: border-box; }   /* set this globally, always */
Key Insight: border-box By default (content-box), width = content only, so padding/border make the element bigger than the number you set. border-box makes width include padding + border — what you set is what you get. Set it on * at the top of every stylesheet.

padding = space inside the border. margin = space outside it. Vertical margins between block elements collapse (the larger wins, they don't add).

7. display: block vs inline vs inline-block ⏱ 1 min

block
Full width, new line. Respects width/height + all margins. (div, p, section, h1)
inline
Flows in text, only as wide as content. Ignores width/height + vertical margins. (span, a, strong)
inline-block
Flows inline BUT respects width/height + margins. Best of both.

And the two big layout displays: flex (1D) and grid (2D) — covered below and in the Grid lesson.

8. Units ⏱ 1 min

Which unit, when
px — fixed, absolute. Borders, small fixed sizes.
rem — relative to root font-size. Default for font-size + spacing (predictable, accessible).
em — relative to the element's own font-size. Padding that should scale with text. Compounds when nested.
% — relative to the parent's dimension.
fr — grid only; a share of leftover space.

9. Flexbox (your 1D daily driver) ⏱ 2 min

.container {
  display: flex;
  flex-direction: row;          /* or column */
  justify-content: center;      /* MAIN axis alignment */
  align-items: center;          /* CROSS axis alignment */
  gap: 1rem;
  flex-wrap: wrap;              /* let items wrap to next line */
}
.item { flex: 1; }              /* grow to share space equally */
justify-content
+ align-items
= centered
The mental model Pick a direction (row/column) = the main axis. justify-content aligns along main; align-items aligns across it (cross axis). Flip flex-direction and those two swap which way they push. Centering anything = display:flex; justify-content:center; align-items:center.
Flex vs Grid Flexbox = content-first, ONE dimension (a row or a column). Grid = layout-first, TWO dimensions. Real pages use both: Grid for the page skeleton, Flexbox inside the pieces.

10. Positioning ⏱ 2 min

position values
static — default, normal flow.
relative — nudge from its normal spot with top/left; keeps its space. Also = anchor for absolute children.
absolute — removed from flow, positioned against nearest positioned ancestor.
fixed — pinned to the viewport, stays on scroll.
sticky — normal until it hits a scroll threshold, then sticks.
The one pattern to remember To place a child precisely inside a parent: give the parent position: relative and the child position: absolute. Absolute always anchors to the nearest positioned ancestor — without relative on the parent it escapes to the whole page.

11. Practical odds & ends ⏱ 1 min

  • Colors: #rrggbb, rgb(), hsl() (hsl is easiest to reason about: hue/sat/light).
  • Centering a block horizontally: margin: 0 auto (with a set width). Centering anything: flex/grid.
  • Reset: start sheets with * { margin:0; padding:0; box-sizing:border-box; }.
  • Fonts: font-family with fallbacks (system-ui, sans-serif); size in rem; line-height: 1.5ish for body text.
  • Overflow: overflow: auto/hidden/scroll controls content that exceeds its box.

Retrieval Quiz

1. Why set box-sizing: border-box?

  • width includes pad+border
  • it removes all margins
  • it centers the element
  • it enables flexbox use
Correct. With border-box, the width you set includes padding + border, so the box doesn't balloon past your number.

2. Which has the highest specificity?

  • an id selector
  • a class selector
  • an element selector
  • a pseudo-element
Correct. id > class/pseudo-class/attribute > element. Inline beats id; !important beats all (avoid it).

3. inline-block differs from inline because it...

  • respects width and height
  • always starts a new line
  • cannot have any padding
  • hides itself by default
Correct. inline-block flows inline but respects width/height/margins, which plain inline ignores.

4. In Flexbox, justify-content aligns along the...

  • main axis direction
  • cross axis direction
  • diagonal of the box
  • the page scroll axis
Correct. justify-content = main axis; align-items = cross axis. Flipping flex-direction swaps which is which.

5. For absolute positioning to anchor to a parent, the parent needs...

  • position: relative
  • display: block set
  • a fixed pixel width
  • overflow set hidden
Correct. Absolute anchors to the nearest positioned ancestor; give the parent position: relative.

6. Best default unit for font-size and spacing?

  • rem, root-relative
  • px, fixed always
  • em, parent-relative
  • percent of screen
Correct. rem is root-relative: predictable, no compounding, scales with the user's accessibility font setting.
