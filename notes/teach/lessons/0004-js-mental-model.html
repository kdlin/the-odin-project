JS Mental Model + Modern Syntax

1. The mental model: how JS differs ⏱ 2 min

Dynamically typed
No type declarations (like Python). A variable can hold anything. Type errors show up at runtime, not compile.
Single-threaded + async
One thread, but non-blocking via the event loop. Unlike Java's threads -- you'll use async/await, not parallelism.
Functions are values
Pass them as arguments, return them, store them. First-class functions are everywhere (callbacks, array methods).
Prototype-based, not class-based
class exists but it's sugar over prototypes -- not Java's class model under the hood. (Detail for later.)

2. Variables: const by default ⏱ 1 min

const name = "Kendrick";   // can't be reassigned -- your DEFAULT
let count = 0;             // use only when you reassign
count = 1;                 // ok
// var -- DEAD. Never use it. (function-scoped + hoisted = bugs)
Gotcha: const locks the binding, not the contents const arr = []; arr.push(1); — totally fine. const stops reassignment (arr = somethingElse), not mutation of the object/array it points to.

3. Arrow functions (JS-native habit) ⏱ 2 min

// classic
function add(a, b) { return a + b; }
// arrow -- concise, implicit return when one expression
const add = (a, b) => a + b;
const square = n => n * n;          // one param, no parens needed
const greet = () => console.log("hi");
Why arrows matter You'll use them constantly as callbacks (arr.map(x => x * 2)) and in React. The big behavioral difference (coming in the Functions lesson): arrows don't bind their own this -- which is exactly why they're the default for callbacks.

4. Template literals ⏱ 1 min

const name = "Kendrick";

// multiline works too, no \n needed

5. Destructuring (you'll see it everywhere) ⏱ 2 min

const user = { name: "K", age: 22 };
const { name, age } = user;          // pull fields into variables

const nums = [1, 2, 3];
const [first, second] = nums;        // pull by position

// super common in React: const [count, setCount] = useState(0);
function greet({ name }) { ... }     // destructure a param directly
Why it matters React's useState, props, and Node's module imports all lean on destructuring. Not knowing it makes React code look like hieroglyphics. Know it cold.

6. Spread & rest (...) ⏱ 2 min

// SPREAD -- expand into a new array/object (immutable updates!)
const more = [...nums, 4];                 // [1,2,3,4]
const updated = { ...user, age: 23 };      // copy + override

// REST -- gather the rest into one
const [head, ...tail] = nums;              // head=1, tail=[2,3]
function sum(...args) { ... }              // any number of args
Why this is load-bearing in React React state must be updated immutably. You never mutate -- you spread into a new copy: setUser({ ...user, age: 23 }). This single pattern shows up in nearly every React component. Master it now.

7. Modules (import/export) ⏱ 1 min

// math.js
export const add = (a, b) => a + b;
export default function multiply(a, b) { return a * b; }

// app.js
import multiply, { add } from "./math.js";   // default + named
Top JS-native gotchas (your Java/Python instincts misfire here) • === not == — == does type coercion (0 == "" is true!). Always use ===.
• Truthy/falsy — 0, "", null, undefined, NaN, false are falsy; everything else truthy. if (arr) is true even for [].
• null vs undefined — undefined = never set; null = intentionally empty. Both falsy.
• Numbers are floats — 0.1 + 0.2 !== 0.3. No separate int type.
• Hoisting — const/let aren't usable before declaration (unlike var). Just declare before use.

Practice: predict the output

const user = { name: "K", role: "dev" }; const copy = { ...user, role: "lead" }; console.log(copy); console.log(0 == ""); console.log([] ? "yes" : "no");
{ name: "K", role: "lead" } (spread copies, then role overrides) · true (== coerces -- exactly why you avoid it) · "yes" (an empty array is truthy -- a classic trap).

Check Your Understanding

1. Default variable keyword in modern JS?

  • const, then let if needed
  • var for everything now
  • let for all variables
  • always declare with var
Correct. const by default; let only when you reassign; var never (function-scoped + hoisted = bugs).

2. const arr = [1]; arr.push(2) -- result?

  • works, arr is [1, 2]
  • error, const is frozen
  • silently does nothing
  • resets arr to empty
Correct. const locks the binding, not the contents. You can mutate the array; you just can't reassign arr.

3. To immutably update an object in React state, you...

  • spread into a new object
  • mutate then call setState
  • reassign the const var
  • delete and rebuild it
Correct. { ...obj, field: newVal } -- spread copies, then override. Never mutate state directly.

4. Why prefer === over ==?

  • no type coercion surprises
  • it runs measurably faster
  • == is a syntax error now
  • === allows null checks
Correct. == coerces types (0 == "" is true); === compares value AND type, no surprises.
