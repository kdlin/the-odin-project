CSS Grid

Intermediate HTML & CSS

Positioning Grid Elements

Vocabulary: track vs line vs cell

  • Track -- one full row or column (the strip between two adjacent lines). You define tracks with grid-template-rows/columns.
  • Line -- the dividers between/around tracks. Created implicitly when tracks are defined; numbered from 1. You position items on lines.
  • Cell -- one row track crossing one column track. The smallest unit.

Key insight: a grid with N tracks on an axis has N+1 lines. A 3x3 grid has 4 lines per axis.

The big mental model: you place items on LINES, not cells

An item's placement is "start on this line, end on that line" -- it fills whatever cells live between. Spanning falls out for free: widen the gap between start and end lines.

/* cell B = 2nd column: start line 2, end line 3 */
grid-column: 2 / 3;
/* span B + C: just move the end line out */
grid-column: 2 / 4;
Gotcha: lines start at 1, not 0. There is no line 0. Use -1 for "the last line" (great for full-width spans). Also start == end gives zero span.

Positioning properties

  • grid-column-start/end, grid-row-start/end -- the longhands; values are line numbers.
  • grid-column / grid-row -- shorthand: start / end.
  • grid-area -- combines all four: row-start / col-start / row-end / col-end (both starts first, then both ends).
  • span keyword -- instead of an end line, say how many tracks to cover: grid-column: 1 / span 2 covers 2 columns starting at line 1. The count is inclusive (span 2 = two tracks total).

grid-area has TWO jobs

  1. Line shorthand: grid-area: 1 / 1 / 3 / 6; -- numbers pointing at lines.
  2. A name: grid-area: living-room; -- assigns a name tag, only works paired with the container's grid-template-areas map.

Named areas: grid-template-areas (3-step recipe)

.container {
  /* 1. SIZE the tracks */
  grid-template-rows: 100px 100px 500px 100px;
  grid-template-columns: 340px 1020px;
  gap: 15px;
  /* 2. MAP the layout with names */
  grid-template-areas:
    "header  header"
    "sidebar nav"
    "sidebar article"
    "footer  footer";
}
/* 3. CLAIM the names on each item */
.header  { grid-area: header; }
.sidebar { grid-area: sidebar; }
  • Each quoted string = one row; each word = which item fills that cell.
  • Spanning = repeating the name: same word across a row spans columns; same word down rows spans rows.
  • . marks an empty cell.
Hard rule: a spanned area must form a solid rectangle. L-shapes/gaps make the whole grid-template-areas invalid (silently ignored).

gap vs margin

gap spaces between tracks only -- no waste on outer edges. margin adds space on all four sides of each item, so gutters double (15+15) and bleed onto edges. Inside grid/flex: use gap for spacing items, reserve margin for spacing from things outside the container.

display: grid vs inline-grid

Inside behaves identically. Difference is the container itself: grid = block-level (full width, new line); inline-grid = inline-level (sits in text flow, only as wide as needed).

px vs fr (preview)

px = static, exact size, does NOT stretch to fill. fr = a fraction of leftover space, splits remaining room by ratio and resizes with the container. 1fr 3fr fills the width 1:3; 1px 3px = two tiny slivers.

Advanced Grid Properties

repeat()

Create many same-size tracks without typing each: repeat(count, size). Size can be any track value (fr, px, %, minmax).

grid-template-columns: repeat(5, 1fr);   /* 5 equal columns */
grid-template-columns: repeat(2, 2fr) repeat(3, 1fr);  /* mix */

Static vs dynamic sizing

  • Static (px) -- fixed, never adjusts to container size.
  • Dynamic (fr, %, auto) -- recalculates as the container/viewport changes.

fr -- distribute leftover space

fr = a share of the remaining space (after fixed tracks + gaps are subtracted). Uneven splits via different values: 1fr 4fr -> 1/5 and 4/5 of leftover space. Note: auto is different -- it sizes to content, not leftover space.

min() / max() / clamp() / minmax()

  • min(a, b, ...) -- returns the smallest value; max(a, b, ...) -- the largest. Global functions.
  • clamp(min, ideal, max) -- global; sits at ideal, clamps to min/max at the boundaries. Works on any property.
  • minmax(min, max) -- grid-only; a track flexes between min and max (clamps at min when shrinking, caps at max when growing). No "ideal" point.
Don't confuse: min()/max() pick from a list; minmax() bounds a single track. clamp() = global with an ideal; minmax() = grid-only without one.

auto-fit / auto-fill -- dynamic track count

Go in the count slot of repeat() (not the size slot). The browser computes how many tracks fit. auto is a size value; auto-fit/auto-fill are count values.

grid-template-columns: repeat(auto-fit, minmax(250px, 1fr));
/* as many >=250px columns as fit, each growing to share leftover (1fr) */

How it computes: browser counts using the min (most columns), then grows each up to the max.

auto-fit vs auto-fill (the reversible one)

Identical when the grid is full. Difference shows only with fewer items than fit:

  • auto-fit -- empty tracks collapse to 0 -> items stretch to fill the row (items FIT the space).
  • auto-fill -- empty tracks stay (ghost columns) -> items keep their size, the row is filled with empty tracks.
Mnemonic: auto-FIT = items FIT/stretch; auto-FILL = row FILLed with ghost columns. 90% of the time you want auto-fit.

grid-auto-rows -- size implicit rows

When the row count is dynamic (e.g. cards from auto-fit), you can't use grid-template-rows. Use grid-auto-rows: 200px to size every auto-created row, or set height on the item directly.

Explicit vs implicit grid

Explicit = tracks you define (grid-template-*). Implicit = tracks the browser auto-creates when items need a row/column you didn't define. Referencing a line (e.g. grid-row: 2 / 4) creates the implicit tracks to satisfy the placement -- you don't have to pre-declare row count.

Rows are global across columns

A grid row line cuts across ALL columns -- you can't have col 1 with 3 rows and col 2 with 4. The column with the most stacked items sets the row count; quieter columns span to match (e.g. a sidebar spanning grid-row: 2 / 4 to cover two rows that the other column split into).

Alignment: items vs content, self vs container

  • justify-items / align-items (container) -- align each item inside its own cell. justify-self / align-self (item) -- same, for one item.
  • justify-content / align-content (container) -- align the whole group of tracks inside the container (only does anything when tracks don't fill it -- e.g. auto columns, not 1fr).
  • place-items: center = align-items + justify-items shorthand (centers content both axes).
  • Axes: justify- = horizontal (inline), align- = vertical (block).
align-items gotcha: default is stretch (item fills its cell -- this is the "auto-growing"). Setting center shrinks the item to content and centers it, so it stops filling. Want fill = stretch; want centered = center.

text-align vs justify-self

text-align aligns inline/text content inside a box. justify-self aligns the whole grid item box within its cell -- use this for a real logo/image (survives content changes), not text-align.
