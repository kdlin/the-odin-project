Positioning Grid Elements

Vocabulary: track vs line vs cell

  • Track -- one full row or column (the strip between two adjacent lines). You define tracks with grid-template-rows/columns.
  • Line -- the dividers between/around tracks. Created implicitly when tracks are defined; numbered from 1. You position items on lines.
  • Cell -- one row track crossing one column track. The smallest unit.

Key insight: a grid with N tracks on an axis has N+1 lines. A 3x3 grid has 4 lines per axis.

The big mental model: you place items on LINES, not cells

An item's placement is "start on this line, end on that line" -- it fills whatever cells live between. Spanning falls out for free: widen the gap between start and end lines.

/* cell B = 2nd column: start line 2, end line 3 */
grid-column: 2 / 3;
/* span B + C: just move the end line out */
grid-column: 2 / 4;
Gotcha: lines start at 1, not 0. There is no line 0. Use -1 for "the last line" (great for full-width spans). Also start == end gives zero span.

Positioning properties

  • grid-column-start/end, grid-row-start/end -- the longhands; values are line numbers.
  • grid-column / grid-row -- shorthand: start / end.
  • grid-area -- combines all four: row-start / col-start / row-end / col-end (both starts first, then both ends).
  • span keyword -- instead of an end line, say how many tracks to cover: grid-column: 1 / span 2 covers 2 columns starting at line 1. The count is inclusive (span 2 = two tracks total).

grid-area has TWO jobs

  1. Line shorthand: grid-area: 1 / 1 / 3 / 6; -- numbers pointing at lines.
  2. A name: grid-area: living-room; -- assigns a name tag, only works paired with the container's grid-template-areas map.

Named areas: grid-template-areas (3-step recipe)

.container {
  /* 1. SIZE the tracks */
  grid-template-rows: 100px 100px 500px 100px;
  grid-template-columns: 340px 1020px;
  gap: 15px;
  /* 2. MAP the layout with names */
  grid-template-areas:
    "header  header"
    "sidebar nav"
    "sidebar article"
    "footer  footer";
}
/* 3. CLAIM the names on each item */
.header  { grid-area: header; }
.sidebar { grid-area: sidebar; }
  • Each quoted string = one row; each word = which item fills that cell.
  • Spanning = repeating the name: same word across a row spans columns; same word down rows spans rows.
  • . marks an empty cell.
Hard rule: a spanned area must form a solid rectangle. L-shapes/gaps make the whole grid-template-areas invalid (silently ignored).

gap vs margin

gap spaces between tracks only -- no waste on outer edges. margin adds space on all four sides of each item, so gutters double (15+15) and bleed onto edges. Inside grid/flex: use gap for spacing items, reserve margin for spacing from things outside the container.

display: grid vs inline-grid

Inside behaves identically. Difference is the container itself: grid = block-level (full width, new line); inline-grid = inline-level (sits in text flow, only as wide as needed).

px vs fr (preview)

px = static, exact size, does NOT stretch to fill. fr = a fraction of leftover space, splits remaining room by ratio and resizes with the container. 1fr 3fr fills the width 1:3; 1px 3px = two tiny slivers.
